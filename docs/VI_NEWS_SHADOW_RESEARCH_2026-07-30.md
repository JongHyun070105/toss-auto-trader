# VI 재개장·뉴스 위험 섀도 연구 (2026-07-30)

## 결론

- 기존 실전 전략의 `VI_DYNAMIC` 제외는 유지한다.
- VI 종목은 `robust_gap5_vi_reopen_shadow_v1`이라는 별도 paper-only 전략으로만 관찰한다.
- 뉴스는 지금 단계에서 수익 신호가 아니라 **악재 누락 위험을 줄이는 섀도 필터**로 사용한다.
- OpenDART/KIND 같은 공식 공시만 자동 위험 차단 후보가 될 수 있다. Naver 일반 뉴스는 문맥 오인 가능성 때문에 검토 태그만 만든다.
- 긍정 뉴스와 뉴스 부재는 매수 승인 근거로 사용하지 않는다.
- 이번 변경은 주문 코드, 실전 VI 차단, 매수 순위, 손절·익절 값을 변경하지 않는다.

두 연구 경로 모두 `paper_only=true`, `order_sent=false`,
`live_order_allowed=false`, `strategy_alpha_claim=false`를 출력한다.

## VI 가설과 실행 기준

사전 가설은 "VI 경고 이후 첫 양수 거래량 1분봉 시가로 진입하면 원래 개장가
지정가보다 체결 현실성이 높아지고, 현재 `-2.25%/+12%/종가청산`으로 비용 후
수익이 남는가"였다.

재현 규칙:

1. Toss 경고 조회 시각이 포함된 `excluded_warning: VI_DYNAMIC`만 사용한다.
2. 경고가 기록된 분은 제외하고 다음 정분부터 탐색한다.
3. 거래량 0 봉은 거래 재개나 지정가 체결로 인정하지 않는다.
4. 첫 양수 거래량 봉의 시가를 재개장 진입가로 둔다.
5. 같은 분에 손절과 익절이 모두 닿으면 보수적으로 손절을 먼저 적용한다.
6. 손절가 아래로 분봉이 시작하면 손절가가 아니라 해당 분 시가로 체결된 것으로 본다.
7. 비용은 기본 `0.35%`, 가혹 `1.35%` 두 조건으로 비교한다.

KRX는 VI 발동 시 연속매매를 2분 단일가매매로 전환한다. 따라서 VI 중 보이는
거래량 0 봉과 개장 시가를 실제 재진입 체결가로 가정하면 안 된다.
[KRX VI 안내](https://global.krx.co.kr/contents/GLB/06/0602/0602020204/GLB0602020204T7.jsp)

## Naver 후보 커버리지 실험

호출은 저장하지 않는 `--print-only`로 실행했다.

| 거래일 | 후보 | 반환 기사 | 72시간·결정 전 적격 | 적격 기사 없는 후보 | 시점 유효 표본 |
|---|---:|---:|---:|---:|---:|
| 07-29 | 5 | 50 | 6 | 1 | 0 |
| 07-30 | 13 | 130 | 34 | 4 | 0 |

모든 조회가 장 마감 후 수행됐으므로 기사 발행 시각이 09:01 이전이어도
`observed_at > decision_at`이다. 성과 승격용 point-in-time 표본은 `0건`이다.

첫 고속 조회에서는 13번째 요청이 HTTP 429로 실패했다. 요청 간격을 0.8초로
늘린 재실행에서는 13개 쿼리와 130건이 모두 반환됐다. 스크립트 기본 간격도
0.8초로 두었으며, 공급자 오류는 뉴스 없음으로 바꾸지 않고 별도 기록한다.

단순 키워드는 `"관리종목 피한"` 기사도 위험으로 오인했다. 이에 따라:

- `피한/해제/철회/해소/상환` 문맥을 위험 키워드에서 제외한다.
- Naver의 강한 악재 단어도 자동 veto가 아니라 `manual_review`로 낮춘다.
- 공식 OpenDART/KIND 공시에서만 hard-risk veto 후보를 만든다.
- OpenDART 키가 현재 로컬 환경에 없어 공시 커버리지 실험은 아직 수행하지 못했다.

OpenDART 공시검색 API는 종목코드, 접수일자, 공시유형을 구조화해 반환하므로 일반
기사보다 우선한다.
[OpenDART 공시검색 API](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019001)

Naver 개발자센터 Search API는 2026-07-30 24:00부터 신규 신청이 중단되고 기존
이용자는 NAVER API HUB 이관 일정의 영향을 받는다. 따라서 Naver를 유일한 장기
공급자로 고정하지 않는다.
[Naver API 이관 약관 공지](https://developers.naver.com/notice/article/32973)

## 뉴스 운영 방침

1. **주문 임계경로와 분리**: 09:01 주문 처리 중 외부 뉴스 API나 LLM을 호출하지 않는다.
2. **공시 우선**: OpenDART/KIND, Toss 경고, 일반 뉴스 순으로 신뢰도를 둔다.
3. **악재만 섀도 veto**: 긍정 기사는 태그만 남기고 매수를 승인하지 않는다.
4. **뉴스 없음은 미확인**: 기사 0건, API 실패, 종목명 매핑 실패를 안전으로 간주하지 않는다.
5. **시점 고정**: `published_at <= decision_at`와 `observed_at <= decision_at`를 모두 만족해야 승격 표본이다.
6. **원문 메타데이터 유지**: 제목·URL·공급자·발행·관측 시각을 남기고 결과를 보고 분류를 바꾸지 않는다.
7. **LLM 격리**: 사후 라벨 보조에는 쓸 수 있으나 실시간 주문 허용값을 직접 만들지 않는다.

시점 유효 표본을 만들기 위해 `simple_gap_news_prefetch.py`가 장 시작 전 KOSDAQ
OpenDART 공시 전체를 한 번 저장하고, 후보가 정해진 뒤의 평가기는 그 스냅샷에서
종목코드가 같은 공시만 읽는다. API 호출 완료 시각이 09:01을 넘으면 그 스냅샷은
자동으로 승격 표본에서 제외된다. Naver는 후보가 정해진 뒤 호출하므로 현재는
보조 진단이며 point-in-time 승격 근거가 아니다.

LLM이 기사 이후의 일반 지식을 이용하면 look-ahead가 생길 수 있다는 검증도 있다.
[GPT 감성분석 look-ahead 연구](https://arxiv.org/abs/2309.17322)

재현:

```bash
PYTHONPATH=src:scripts .venv/bin/python scripts/simple_gap_news_prefetch.py \
  --date 2026-07-30 --print-only
PYTHONPATH=src:scripts .venv/bin/python scripts/simple_gap_news_shadow.py \
  --date 2026-07-30 --max-candidates 13 --print-only
```

## 승격 기준

### VI 재개장 전략

- 실제 포착 VI 최소 50건
- 기본·가혹 비용 모두 잠금구간 순손익 양수
- 기존 VI 제외 후 다음 순위 전략보다 순손익과 MDD가 모두 개선
- 재개장 가격, 호가/스프레드, 주문 가능 시각 누락 0건

### 뉴스 위험 필터

- 최소 60거래일 및 후보 100건의 `observed_at <= decision_at` 전진 표본
- 공식 공시 수집 성공률 99% 이상, 종목코드 매핑 오류 0건
- 차단으로 피한 손실에서 차단 때문에 놓친 수익을 뺀 잠금구간 효과가 양수
- 일반 뉴스 자동분류는 별도 수동 라벨 100건에서 정밀도 90% 이상이 되기 전까지 검토 태그로만 유지

현재는 어느 승격 기준도 충족하지 않는다. 섀도 로그와 연구 스크립트만 추가하며
실전 cron에는 자동 등록하지 않는다.
