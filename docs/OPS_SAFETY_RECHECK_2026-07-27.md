## 결론

수익률을 높인다는 이유로 갭 하한, 시장 가드, 손절, 익절 조건은 변경하지
않았다. 최신 DB와 기존 백테스트를 다시 비교해도 현재 전략값을 바꿀 근거가
없었다. 대신 실제 주문이 잘못된 가격으로 대기하거나, 일봉 DB에 다른 주기가
섞여 기준일이 오염되는 경로를 차단했다.

않았다.

## 반영한 개선

### 1. 일봉 DB 주기 고정

`scripts/simple_gap_trader.py`의 전일 종가, 전일 거래량, 직전 20일 평균 거래량
조회에 모두 `interval='1d'` 조건을 추가했다. 향후 같은 DB에 1분봉이나 다른
주기 캔들이 들어와도 일봉 전략의 기준일과 거래량 평균을 오염시키지 않는다.

### 2. stale 저가 호가 방어

주문 직전 호가의 최우선 매도호가가 스캔 당시 마지막 현재가보다 낮으면 낮은
호가를 그대로 지정가로 사용하지 않고 최근 현재가 이상으로 보정한 뒤 추격 한도를
다시 평가한다. 보정된 가격이 시가 대비 `0.5%` 한도를 넘으면 주문하지 않는다.

예를 들어 시가 1,372원, 최근 현재가 1,498원, 호가 1,372원이 반환되면
1,372원 주문을 대기시키지 않고 1,498원 기준으로 재판정해 매수를 차단한다.

## 남은 한계

- `/prices`와 `/orderbook` 응답의 서버 시각이 제공되지 않는 경우, API 응답의
  실제 신선도는 완전히 증명할 수 없다. 현재는 최근 현재가와 호가의 가격
  불일치를 이용한 fail-closed 방어를 적용했다.
- 일봉 백테스트는 실제 주문 대기열, VI, 체결 지연을 재현하지 못한다.
- 이 점검은 전략 알파를 새로 발견한 것이 아니라 운영 오류 가능성을 줄인 것이다.
